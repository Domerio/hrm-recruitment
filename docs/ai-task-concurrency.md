# AI 并发与采集动作

工作台版本：0.5.65；兼容当前采集扩展 0.5.110。

## 收藏和转发

这次保留扩展现有顺序：完整读取当前候选人 → 等待 AI 分析结果 → 根据本次采集规则保存、收藏、转发 → 读取下一人。工作台提交的其他简历可以同时分析。扩展仍在执行平台动作前核对当前候选人身份；网络请求失败会暂停，不会自行把未收到的分析结果当作评分结论。

如果以后要让单个扩展采集窗口先连续采集、随后统一分析，需要再增加平台动作队列：保存招聘账号、候选人唯一标识、岗位和采集规则快照，分析完成后重新打开对应候选人，核验身份后执行收藏/转发；无法可靠返回或核验时交给人工处理。本版本未启用这种分离方式。

## 使用

- 在“连接与集成 → AI 任务与并发”查看公共任务和修改并发数。默认 3，可选 1–8；运行或排队期间不能更改。配置保存在本机 data/ai-runtime.json，与模型密钥配置分开。
- 工作台单人重试和批量评估统一提交服务器任务。所有访问工作台的电脑和采集扩展共用并发上限，避免各自启动一批后超出限制。
- 队列最多等待 100 项；工作台批量每次保留最多 50 项尚未结束的任务，完成后继续提交剩余名单，收到明确的队列已满响应会等待再试。
- 批量进度区区分等待提交、正在提交、排队、运行、成功、失败及停止等待。停止会撤回本批尚未提交的候选人，并释放本批已提交任务的订阅；还有其他人等待的共享任务继续执行，已运行的任务继续完成并保存。
- 刷新/关闭网页不会停止服务器已接收的任务；尚在页面中等待提交的名单需要重新选择提交。重新提交已评估且资料未变化的候选人会复用有效评估。

## 一致性和限流

候选人、岗位和模型等有效输入相同的在途评估共享任务；资料在等待期间变化会要求重新提交，避免用旧输入覆盖新资料。评估落库时再次核对来源及已有有效结果。状态列表只包含任务摘要，不包含简历正文、请求密钥或取消凭据。

模型返回 HTTP 429 时，按 Retry-After 或短暂退避最多重试 2 次，同一服务及凭据共用冷却时间，每次调用累计冷却等待不超过 60 秒。连接超时、连接中断等结果不明确的情况不会自动重发模型请求。既有模型格式校验重试仍然保留。

任务队列在服务内存中，保留最近 200 条已结束任务；评估结果保存在数据库。重启服务不会恢复未完成任务，更新/重启前应等任务结束；重启后刷新候选人列表核对并重新提交未完成项。

## 验证

验证只使用临时数据库、合成简历和模拟模型；覆盖多人同时提交、全局并发上限、重复合并、停止与共享订阅、排队期间资料变化、持久化设置、429 冷却、以及大批名单滚动提交。未调用真实付费模型，未发送 BOSS 消息，未触发真实收藏或转发。
