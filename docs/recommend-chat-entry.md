# 推荐牛人聊天入口

工作台 0.5.66，扩展 0.5.113。

## 好友关系限制与修正

2026-11-20 用户实测推荐候选人链接提示「该牛人不在好友列表，无法沟通」。已保存的 BOSS 官方代码确认：聊天路由按 `friendId + friendSource` 查询当前账号的好友记录，结果为空即返回该提示。`geekBaseInfo.userId` 只证明候选人身份，不证明当前账号已经建立沟通关系。此前将所有推荐 UID 直接显示成「在 BOSS 中聊天」不准确。

工作台已将推荐来源的按钮改为「联系候选人」，先展示联系选项和关系未核实提示。可复制姓名、打开推荐牛人列表，在官方简历中核对候选人及岗位后自行打招呼；通用列表入口不会自动定位该候选人。已沟通过的候选人可尝试打开已有会话。工作台「聊天与附件」和「沟通记录」中已导入的绑定会话保留按招聘账号展示的直接跳转。仅有推荐 UID 的档案不再计入「已获取联系方式」或「有平台入口」。

没有新增自动打招呼、消息发送或好友关系接口调用。历史 UID 保留为身份信息；未找到已验证可直接打开陌生候选人详情并联系的永久链接。

## 使用

重新加载扩展并重新打开采集窗口，在「推荐牛人」正常采集。采集器在当前卡片与完整简历身份一致时读取真实数值 UID，保存为候选人独立的联系标识。不会点击打招呼，也不会自动发送消息，采集结果不证明好友关系。

在工作台候选人详情顶部、联系与回访，或候选人列表的更多操作中点击「联系候选人」。请在打开链接的浏览器中使用建立该会话的招聘账号登录 BOSS，并核对候选人及沟通职位。平台账号权限、是否已有沟通关系及平台当前行为决定能否实际联系；换账号可能再次出现非好友提示。

旧档案不会凭姓名生成链接；再次采集遇到同一推荐卡时可以补采。仅缺聊天入口的旧档案不重新评估，也不重复已完成的收藏或转发。字段缺失不影响简历归档；身份冲突或已有不同 UID 时拒绝覆盖。搜索列表暂不加入该补采逻辑。

若只想补齐旧档案，在采集窗口点击「仅补采聊天入口」。此操作仅处理启动时当前列表中、所选岗位下已归档且缺入口的推荐牛人；人数留空则处理这一批全部。它只核验当前卡片、详情身份及聊天 UID，不重新复制整份简历，不应用岗位筛选、不自动翻页或持续等待，也不评估、收藏、转发或读取二维码；未完成的这些动作仍保留原状态。

## 数据与校验

- UID 来源：当前可见推荐详情 `ResumeRoot.resumeInfo.geekBaseInfo.userId`，仅接受规范正整数；加密候选人 ID 只作卡片与详情身份匹配，不能作为 UID。
- MAIN 读取函数独立、只读，范围限定当前唯一可见详情及其 Vue 组件；不调用页面方法、不发网络请求、不读取 Cookie、请求头或 `securityId`。
- 采集器在完整简历校验通过后连续两次核验 UID 和身份，保存后通过独立的 `/api/extension/chat-entry` 请求补入元数据，不受 AI 队列任务合并或缓存影响。
- 服务端验证候选人、岗位、来源卡片唯一映射，保存到 `candidate_sources.boss_chat_uid`；不覆盖原简历链接、二维码、评估、收藏或转发状态。
- 聊天链接固定为 `https://www.zhipin.com/web/chat/index?uid=<数值 UID>&source=0`。

## 证据范围

某位候选人的数值 UID `<会话UID>` 已由正常界面操作的网络日志确认，用户确认该链接可以聊天。该次验证发生在成功点击「打招呼」之后，不能推广到未沟通的推荐候选人，也不证明链接跨账号或永久有效。

自动读取链路用合成详情和模拟 API 验证，另已在真实推荐详情中补采 UID；平台若更改字段或未提供数值 UID，采集器保留简历而不生成会话尝试链接。真实补采成功也不能证明当前账号的好友关系。
