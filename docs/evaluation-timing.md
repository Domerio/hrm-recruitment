# 简历评估本地耗时与模型内容日志

每个实际执行的评估任务自动生成 `data/evaluation-logs/YYYY-MM-DD/<trace_id>.jsonl` 耗时明细和同名 `.summary.txt` 中文摘要。发生模型调用时，另生成同名 `.payloads.jsonl` 内容文件。日期及时间使用北京时间，耗时使用单调时钟，单位毫秒。前端和原评估接口不增加显示或日志字段。

摘要包含提交准备、公共队列等待、执行总耗时、缓存查询、输入准备、每轮模型请求、限流等待、响应读取及解析、格式/证据校验、评分、结果保存。数据库阶段包含事务提交或回滚。JSONL 逐步写入，进程意外退出时可根据最后一条阶段开始事件定位中断位置。

同时记录候选人/岗位/任务编号、模型、配置版本、评估代次、缓存命中、HTTP状态、失败类型及模型报告的 Token 用量（包括可用的缓存和推理Token）。格式校验重试、HTTP 429 重试及共享在途推理等待都会留下事件。重复提交共享同一任务，不重复创建日志；取消排队任务仍记录取消及等待时间。

按用户要求，内容文件完整保留实际发送给模型的请求体和模型返回体，包括履历、提示词、模型回答及其返回的推理文本，不截断正常内容。它们可能包含姓名及其他简历信息，仅保存在服务器本机，不返回前端。耗时明细仍只记录阶段和指标，不混入正文。

内容记录含 `trace_id`、北京时间、相对执行耗时、`span_id`、`kind`、`call_id`、HTTP 状态及可用的完整性标识。通过 `call_id` 配对一次模型调用的请求和响应，格式校验重试会形成另一对记录。字节响应按 UTF-8 解码，无法解码的字节使用替换字符，并标记 `payload_encoding=utf-8`、`decode_errors=replace`；非 JSON 错误正文仍可查看。`response_complete=false` 表示仅收到部分响应，不应当作完整模型结果。

密钥、Authorization、access/refresh token、password、secret 等认证字段递归替换为 `[REDACTED]`；正文中回显的当前密钥、Bearer/Basic 认证值和显式 `api_key=...` 等也脱敏。JSON 内嵌的 JSON 字符串同样处理。脱敏可能改变 JSON 的空白格式，但不会为控制长度而删掉正文。HTTP 请求头与接口地址不作为日志元数据写入；正文中的普通网址和非认证字段保留。

文件逐条写入；内容文件写入失败不影响评估及其他耗时日志，摘要会标明失败。命中缓存、取消排队等没有实际模型调用的任务不会生成内容文件。日志没有自动清理策略，需要时可自行归档或按请求清除本地日志；清除这些文件不等于删除数据库里的评估历史。

## 如何阅读

- 阶段总耗时包含其子阶段；自身耗时扣除子阶段，不能把所有阶段总耗时直接相加。
- 服务端工作流总耗时为提交准备 + 排队 + 执行，不包含浏览器读取简历、上传、OCR及页面刷新。
- `http_request` 是建立请求至收到响应头的等待，`response_body_read` 是读取完整响应体；非流式接口无法精确分离网络、服务端排队、预填充、思考和生成，也不能测首Token延迟。
- 命中缓存时没有实际模型请求；并发落库竞争也可能在真实请求完成后复用已保存结果，因此需同时看 `http_request` 的实际次数。
- 失败重试的 Token 会累计；供应商没有报告的字段保持缺失，不用 0 猜测。
- 每次有效切换评估模型会递增 `evaluation_epoch`。A→B→A 会重新调用A；历史保留。同一代次且资料不变的重复请求仍可复用。只编辑非活动模型、显示名称或重复保存同一配置不重置缓存。

## 单份真实调用分析

在项目目录运行 `python scripts/profile_resume_evaluation.py`，默认选择最近一次已评估的候选人，也可用 `--candidate-id 123` 指定。此命令会真实调用当前配置模型，并保留现有的有界重试。

脚本对一致性数据库快照运行完整评估与保存链路，只在快照清除该候选人的缓存以保证真实调用。不会新增正式候选人记录、修改真实模型配置或执行BOSS平台动作。快照自动清理，日志和额外的 `.analysis.txt` 保存在上述日志目录。保存耗时是快照数据库上的测量，未包含真实并发写入争用。

旧评估记录没有这些阶段时长，无法追溯补算；部署后的新任务才会生成日志。
