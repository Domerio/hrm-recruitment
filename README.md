# HRM 招聘辅助模块

当前工作台版本：0.5.41。

候选列表筛选集中在各列表头的漏斗菜单，支持组合筛选、单列重置及清除全部；不再使用表格上方的独立筛选区。窄屏合并列仍提供被合并字段的筛选入口。拖动表头右边界可调整列宽，也可用左右键、Home或双击操作；列宽按本浏览器的宽屏/窄屏布局分别记忆，支持重置，超出可用宽度时只在表内横向滚动。

AI详情中每项依据单独合并重复原句（只归一化空白，保留不同日期、标点及职责），长依据默认简要展示，可展开查看全部独特原文。原始简历、历史评估、逐项判断和分数不因展示去重而改写；新评估在验证所有引用行号后也合并重复原句，避免把同一段采集重叠内容反复列出。

跨多段任职日期和职责的证据允许每项最多48条不同原文依据，仍先逐条核实所有行号的整数类型、简历范围，再合并重复引用，不截断或丢弃非法引用。提示词默认鼓励精简引用，复杂年限可在自动修复时使用更完整的证据；已有有效评估缓存继续复用。格式失败提示会说明具体条件及原因。

候选人表格随可用宽度自动调整：宽屏展示全部列，缩放或窄窗口时将日期、联系方式、城市学历和复核状态归并到对应候选人资料中；行操作在“查看详情”和“更多”中，批量导出在“导出所选”菜单中。技能资料按标签换行展示，可查看提取来源和复制原文。

- 岗位只维护一份要求，在每条要求后勾选“必备”；评估逐条核对必备项，未满足不能进入推荐，信息不足标为待核实。旧版独立必备条目会在编辑时匹配合并，未匹配的真实要求保留到要求列表，保存后应用。
- 默认按要求编号排序，每条要求独立一级，无需手动新增优先级。拖入组内可合并同级，拖到组间虚线可独立成级，整组可换序，编号自动连续、空组自动移除；同组等权，从高到低权重为组数至 1。已自定义保存的组合仍保留。
- 分数由服务端固定规则计算：满足得该项100%；信息不足但有经核验的项目或子项原文证据、标为项目推断并说明已支持部分和缺口时，按10%到90%、每10%一档计分；完全无依据、只有关键词、缺少推导说明及不满足均得0%。模型给出单项support_score，服务端严格检查档位、状态及证据，不能靠任意总分或置信度加分。全部岗位条件仍计入分母和总权重，同一要求同时为必备和一般条件时只计一次。必备项部分支持仍是待核实，不能当作已经满足。相同当前资料、岗位要求、优先级、模型及评估月份复用有效评估。
- 明确配置本科全日制、硕士及以上可非全日制的岗位，最高学历只有非全日制本科时由服务端校正为不满足并计0分，保留模型原判断及校正依据，正常保存其余评估。真实本科学历未标明学习形式时，按岗位默认全日制处理并注明默认来源；不把缺少学历证据默认成已有本科学历，不据此自动通过专业等其他子要求。硕士非全日制不因学习形式被拒，形式矛盾或明确待确认时仍保留核实。继续核对专业及是否已取得学位，不把在读或计划报考算成已取得。
- 完整旧评分快照会在本地沿用原优先级、逐项判断和证据重算，并保留原分数、分类和规则；不完整旧结果标记待重评。新版提示词明确区分部分支持与无依据，旧提示词的缓存不跨该语义变化复用；重新评估时才由模型检查原先未记录的部分支持证据，不会在迁移中补造依据。原历史摘要和人工复核保留。
- 对模型已经明示的合计时长与最低年限门槛作保守一致性复核，例如44个月不能判满足4年；发现矛盾时触发修复，不能作为有效结果保存或从缓存直接复用。未明示总计、单段时长或不明确相关性不会被此检查擅自加总或改分。
- 候选人表格支持 10/20/50/100 条分页、跨页勾选，展示公司职位、城市学历、北京时间的导入时间，以及必备条件状态。列表顶部的“批量评估”可选择当前筛选内未评估和待重试、选中名单、或当前筛选全部；开始前显示人数和岗位分布，按开始时的名单快照串行执行，显示进度并可在当前请求完成后停止。无须先勾选才显示入口；AI列分数与结论同排，必备状态另行显示。
- 候选人的最近公司、职位、城市、学历和技能标签从已复制的简历自动提取，采集导入和保存时自动写入，服务启动时补全旧记录；不调用模型或 OCR。未识别内容保留空白，可查看简历原句来源并人工修正，人工修改或主动清空的字段不会被后续自动填充覆盖。城市可来自明确的期望城市，最近工作不等同于仍然在职。
- 候选人仍可维护姓名、关联岗位、公司职位、城市、学历、技能、手机、邮箱、微信、平台链接、履历和备注。人工维护的职业补充资料参与评估；自动提取值已在原文中，不重复作为人工证据。联系方式和备注不发送给模型。修改履历会重新排版，保留来源和二维码，相关旧评估标待重评。
- 岗位要求、优先级或评估相关资料修改后旧评估保留为历史并标待重评。编辑采用版本检查，避免旧表单覆盖新资料。岗位标题、工作地点、候选人联系方式和备注的单独修改不触发重评。
- “清空评估记录”会清除全部评分、评估历史及对应缓存，保留岗位、候选人资料和来源图片；运行中的 AI 任务须结束后才能清空。

本地开发原型，Python 3.11+。运行 `python -m pip install -r requirements.txt` 安装依赖，然后运行 `python server.py`，访问 http://127.0.0.1:8765 。也可在 PowerShell 中运行 `./start.ps1`。

后台运行：`./start-background.ps1`；更新服务：`./restart-background.ps1`。服务管理脚本需要 requirements.txt 中的 psutil，会核对 Python 程序、脚本路径和工作目录后清理本项目的重复监听进程。服务端 0.5.1 在 Windows 使用端口独占，避免多个旧新版本同时响应 8765。`python service_control.py status` 显示监听进程和实际服务版本；`GET /api/health` 提供不含岗位资料或令牌的就绪检查。现有 0.5.0 插件可直接连接此服务版本。

0.5.30 还支持「展开全部16个所获荣誉」等动态折叠控件；旧记录仍含折叠控件时会在下一次采集补读。分享卡在本机解码二维码，详情中可打开平台简历或复制链接，旧图片可手动补识别。链接访问仍受平台登录、权限及有效期限制。

AI 评估可从项目任务补充相关能力，区分明示、项目推断和资料不足，并保留真实原文依据、推导说明及核实问题。补充能力不改写简历，不重复计分，不根据项目名称或海外客户推断语言等级；旧评估点击「重新评估」后应用新规则。

## 配置

工作台使用 React 和 Ant Design。修改 `frontend/` 后，运行 `npm ci` 和 `npm run build`，再刷新浏览器。构建产物位于 `static/`，日常运行由本地 Python 服务直接提供页面和资源。

浏览器扩展 0.5.30 使用单一的批量采集流程。人数默认留空，持续采集直到点击「停止」；当前列表处理完后尝试滚动加载，或操作唯一明确的「加载更多／下一页」入口，暂无新候选人时每隔 3 秒检查。人数可选填正整数，不再有 20 人上限；填写人数时达到数量或当前可用列表处理完毕即结束。每次发现新卡片都会按岗位查询已保存记录，自动跳过已完成记录，已保存履历仅缺回访图片时只补充图片。卡片和简历身份忽略头部活跃状态、热搜等变化，保留实际任职和教育事实。保持 BOSS 小卡片列表打开，启动后逐人点开详情，展开折叠项，从剪贴板复制履历。插件自动核对姓名、章节和正文完整性，通过后保存并继续下一位。进度会读取 iframe 外层的实际滚动容器；仅重绘画布时，以相邻复制正文的唯一重叠和明确的平台页尾确认连续读取。AI 评估选择简历行号，工作台显示对应的原文依据。履历和已勾选的二维码保存后，AI 依据未通过校验的候选人记为待评估，批次继续下一人。折叠未展开、正文漏读或资料保存失败时停在当前候选人重试。安装、授权和使用方法见 [插件安装说明](extension/安装说明.md)。

工作台 0.5.30 在纯文本履历的工作／项目条目末尾识别连续技能标签，支持普通职责段落之后的标签、带空格的技能名和较长标签组。标签横向排列并自动换行，同组重复标签仅展示一次；原始履历与 AI 依据保持原文。现有记录、插件预览和导出 HTML 均使用相同排版，刷新详情即可生效，无需重新采集。

在“连接与集成 → AI 模型配置”维护提供商、API 基础地址、密钥与模型 ID，保存后可读取模型列表或测试连接。支持 DeepSeek 与 OpenAI 兼容的内部服务，模型 ID 也可手填；内部服务可不填密钥。留空密钥表示同服务下保留，明确清除或切换提供商/API 地址后不会继承旧服务密钥。配置保存在服务端 `data/ai-config.json`，前端不读取密钥明文，网络请求不跟随重定向；改变有效配置后相关旧评估标待重评。

首次未保存界面配置时，仍从 `.env` 的 `DEEPSEEK_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 读取原配置。保存后的界面配置优先，更新不需要重启。静态资源采用白名单，不能通过 HTTP 下载配置或数据库。

## 当前可用

- DOCX / UTF-8 TXT 岗位导入，JD 粘贴、AI 条件草稿、人工确认后保存岗位。
- 已保存岗位表格搜索、分页、候选人数排序、配置展开及按岗位跳转候选人名单。
- 手动录入候选人及三类联系方式，组合筛选岗位、关键词、AI 状态、结论、联系方式和复核状态，按分数、姓名或入库时间排序。
- DeepSeek 连接测试、候选人评估、JSON 结构与原文依据校验、历史结果保留。
- 人工复核、备注、勾选候选人并导出带 BOM 的 CSV，包含公式注入防护。
- 候选人单条、批量删除。移出名单后保留采集标记，扩展会跳过该记录。
- SQLite 持久化，BOSS 官方登录入口，模块集成边界清晰。
- 在线简历来源状态、候选人回访二维码图片保存/下载/补充，名单＋履历＋图片 ZIP 导出。缺失信息与采集待核对状态单独显示。

## HRM 接入

当前仅本机回环访问，进程级随机请求令牌用于防跨站写入，不是用户身份认证。正式接入 HRM 时须替换为宿主可验证身份及组织/岗位权限，并对所有读取、评估和导出接口执行鉴权。不要将此开发服务直接暴露到局域网或互联网。

API：`GET /api/state`；`POST /api/jobs`、`/api/extract`、`/api/candidates`、`/api/review`、`/api/ai/criteria`、`/api/ai/evaluate`、`/api/ai/test`、`/api/export`。写请求为 JSON，需 `X-App-Token`。业务错误返回 400，令牌或来源不合法返回 403，模型忙返回 409。具体字段见 `server.py` 和前端调用。

后续内部模型实现 `CompatibleModel.complete(instruction, payload)` 同等契约即可。资料会先移除常见手机号和邮箱，仍应在使用外部 API 前确认实际资料的发送范围。

## 验证

运行 `python -m unittest discover -s tests -v`。测试使用临时数据库，不污染业务数据。DeepSeek 真实连接须有网络、有效密钥和额度；UI 的连接测试仅发送测试消息，不发送候选人信息。

插件测试：`npm ci` 后运行 `npm test`（Node 24）。手动点选浏览器回归：运行 `python tests/picker_preview.py`，访问 `http://127.0.0.1:8876/iframe`。测试页仅包含虚构资料，覆盖跨源 iframe 内点选与读取；服务只公开白名单测试资源，生产代码的 BOSS 域名限制仅在测试页所用副本中移除。

Canvas + 本机 OCR 浏览器回归：运行 `python tests/canvas_preview.py`，访问 `http://127.0.0.1:8878/`。虚构画布覆盖“查看全部”点击、展开后文本、滚动与底部内容读取；不是实际 BOSS 页面验证。

API 实现参考：https://api-docs.deepseek.com/guides/json_mode/

AI 输出的字段格式或证据校验首次失败时，0.5.30 会带具体 schema 错误位置自动修复一次。两次仍失败则保留历史评估并标待重试，不保存无效结果；批量采集在履历和图片保存完成后继续下一位。连接、鉴权和超时故障不自动重复请求。

工作台 0.5.31 会在评估时提供上海时区的当前日期，以及仅依据工作经历原文计算的年月时间线。明确任职日期可用于计算年限，重复或重叠区间只计算一次，教育和项目日期不叠加工龄；日期不完整时标为不确定。岗位相关性仍需根据实际职责逐段判断，不把全部工作月份自动视为细分岗位经验。逐项依据支持同时引用多行日期和职责，分别核对并展示原文；既有单行历史评估保持可读。
